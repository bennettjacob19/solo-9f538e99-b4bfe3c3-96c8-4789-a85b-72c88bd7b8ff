# 固件 CI 工作盘演练

一个 Flask 单页演练台：容量吃紧时，验证「删掉哪些中间产物、重跑哪些步骤」
仍能把目标固件产物构建出来。规划先行——**有解才串行落盘，无解只提示、
一个字节都不写**；执行全程按真实目录占用做硬约束并记录峰值。

## 快速开始

### Docker Compose（推荐）

```bash
docker compose up --build
# 打开 http://localhost:8000
```

### 本地运行

```bash
pip install -r requirements.txt
python app.py            # 或 gunicorn -b 0.0.0.0:8000 app:app
```

### 试跑与核对（无需浏览器）

```bash
python verify_samples.py
```

会跑通：样例A（保留产物）、样例B（删后重建）、无解情形、写失败路径、
Web 冒烟（含真实下载目标产物），并逐项核对实际落盘字节数与占用峰值。

## 页面玩法

1. 填最多 10 个步骤：名称、依赖（逗号分隔）、产物字节数；
2. 选目标步骤，设「产物占用上限」（字节）与「重跑总次数上限」；
3. 点「求解并执行」，或直接用内置样例 A/B 一键载入/试跑；
4. 页面列出实际执行 / 删除 / 重跑顺序、每步后占用与峰值；
   成功后出现目标产物下载链接。

## 规则定义

- **产物内容**：`SHA-256(步骤名 + 各依赖文件内容摘要)` 派生的计数器字节流，
  长度等于所填字节数。删除后重建得到逐字节一致的内容。
- **依赖保护**：构建期间依赖文件必须在盘上，回收只发生在步骤之间。
- **占用口径**：写新产物时，保留文件与未写完的半成品（`.part`）都计入额度；
  执行器每写一块前实测运行目录，超限即停。
- **重跑**：某步骤的产物被删后再次需要时重建，每重建一次计一次重跑；
  规划器按字典序最小化 `(重跑次数, 构建次数, 删除次数)`——非必要不回收。
- **失败处理**：写入失败（超限或 IO 错误）立即停下，删除半成品，
  运行元数据标记 `failed` 并在页面报告。

## 内置样例

| 样例 | 场景 | 容量 | 重跑上限 | 预期结果 |
| --- | --- | --- | --- | --- |
| A | 5 步固件链，容量=全部产物之和 1 500 000 B | 1 500 000 | 0 | 0 删除 0 重跑，峰值 1 500 000 |
| B | `extract_keys` 被 `pack_image` 挤下盘、为 `seal_device` 重建 | 800 000 | 1 | 恰好 1 次重跑，峰值顶到 800 000 |

把样例B 的重跑上限改成 0 即可看到「无解且不写产物」的提示。

## 目录结构

```
app.py            Flask 应用与路由
planner.py        校验 + Dijkstra 规划器（状态=在场集合×曾建集合）
executor.py       串行执行器：分块写、额度硬约束、峰值采样、失败清理
samples.py        内置样例 A/B
verify_samples.py 试跑与核对脚本
templates/        单页模板
runs/             运行产物目录（每次运行一个子目录 + 一份 .json 元数据）
```

## 已知缺项

- 规划目标是最小化 `(重跑, 构建)`，不显式优化峰值；峰值是执行实测值。
- 仅串行执行（题目要求），无并发构建模型。
- 旧运行目录不自动清理，需手工清 `runs/`。
- 无鉴权与多用户隔离，仅作演练；单步产物限 64 MiB、容量限 1 GiB 防误填。
- 写失败没有 UI 注入开关，靠额度硬约束或真实 IO 错误触发（脚本已覆盖该路径）。
